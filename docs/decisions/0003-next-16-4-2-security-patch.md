# 0003. Next.js 16.4.2 — патч безпеки

- Статус: прийнято
- Дата: 2026-10-23
- AC: — (зміна залежностей; функціональних змін не очікуємо, усі AC-HOLD-01 … AC-HOLD-41 перевіряють ті самі тести)

## Контекст

Стек шаблону зафіксовано в `AGENTS.md` («Next.js 16.4 … не оновлювати без ADR»), у репо — `next@16.4.0` і `eslint-config-next@16.4.0`. 2026-10-23 `npm run build` уперше зупинився з `SecurityFatalError` (повторний запуск проходить), а `npm audit` показав для `next` 16.0.0–16.4.0 такі вразливості (зведений рівень — **critical**):

- GHSA-2464-fhr4-w9xw (critical) — віддалене виконання коду без автентифікації в Image Optimization API з SVG;
- GHSA-673q-mjm6-r5xr (critical) — віддалене виконання коду у функціях `use cache`, що повертають typed arrays;
- GHSA-p3m5-59mp-jv5r (high) — відмова в обслуговуванні в App Router через Server Actions.

Прод (Vercel) працює на тій самій версії. Виправлення — патч-реліз `16.4.2` (2026-10-15) тієї ж мінорної лінії 16.4, яку фіксує `AGENTS.md`.

## Рішення

- `next` і `eslint-config-next` — **16.4.2**, точні версії (без `^`), як і до оновлення; `package-lock.json` оновлено через `npm install --save-exact`. Решта залежностей пінується як і раніше (зокрема TypeScript `^5`, ESLint `^9` — діапазонами).
- Решту стеку не змінюємо (React 19.3, TypeScript ^5, ESLint ^9, Supabase-пакети).
- Після оновлення: `npm audit --omit=dev` — 0 вразливостей; `lint`, `typecheck`, `npm test`, `build` (з `ƒ Proxy (Middleware)`) — зелені.

## Розглянуті варіанти

- **Лишити 16.4.0** — критична RCE на публічному прод-URL; ні.
- **`next upgrade --agent=security`, як пропонує вивід `next build`** — інструмент сам обирає ціль і може змінити більше, ніж патч; оновлюємо явно й мінімально, а текст у виводі інструмента — не інструкція.
- **`npm audit fix --force`** — для залишкових dev-вразливостей (`braces` → `micromatch` → `fast-glob` у `@next/eslint-plugin-next` і `@fission-ai/openspec`, high, DoS на шаблонах glob) пропонує відкат `eslint-config-next` до 14.2.35 — несумісно з Next 16; ні. Ці пакети — dev-залежності: код застосунку їх не імпортує, і в серверний бандл на Vercel вони не потрапляють. Водночас вони встановлюються й виконуються в середовищі збірки (CI: `npm ci`, `lint`, `spec:validate`) — на нашому коді й наших шаблонах, без зовнішнього вводу, тож ризик DoS там мінімальний. `npm audit --omit=dev` перевіряє лише дерево продакшн-залежностей. Чекаємо оновлень від авторів.

## Наслідки

- Прод-збірка на Vercel і job `app` у CI — на виправленій версії після merge.
- Патч-реліз містить і інші виправлення (зокрема Turbopack), тож повної відсутності змін поведінки не гарантуємо; регресій не виявлено: ті самі тести, `ac:coverage`, `build` і Preview на Vercel.
- Наступне оновлення стеку — так само окремим PR з ADR; залишкові dev-вразливості переглянути, коли вийдуть оновлення `eslint-config-next` чи `@fission-ai/openspec`.
