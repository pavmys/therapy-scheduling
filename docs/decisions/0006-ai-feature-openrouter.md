## Контекст

Зріз 4 (HryhoriiHaponiukQuitCode/therapy-scheduling-spec#36) додає у форму нової картки клієнта помічника: планувальник
вставляє текст звернення (до 2000 символів, лише текст), застосунок заповнює поля картки чернеткою, а картку створює
лише людина наявною дією `createClientCard`. Обмеження:

- Next.js 16.4 на Vercel Hobby: функція — до 300 с; Server Action — тіло до 1 МБ за замовчуванням.
- Модель — безкоштовна через OpenRouter, ключ — власний. Ліміт — 20 запитів/хв і 50/день на акаунт; його ділять
  живий eval, UAT і приймання PM (10 golden cases на проді). Безкоштовні моделі з'являються й зникають.
- Безкоштовні ендпоінти можуть зберігати запити й навчатися на них → лише синтетичні дані (`*@example.test`);
  PM просить не вставляти діагнози (підказка під полем).
- Відповідь моделі недетермінована, а CI має працювати без мережі й без секретів.
- PM фіксує точні поля й повідомлення (golden cases GC-01…10, поріг ≥ 8/10, обов'язково GC-09 і GC-10).

## Рішення

- Нові залежності (точні версії): `ai@7.0.162`, `@openrouter/ai-sdk-provider@3.1.0`, `zod@4.6.7`,
  `server-only@0.0.1`.
- Виклик — `generateText` + `Output.object({ schema })` (AI SDK 7); схема zod — `status: ok | refused` і поля
  картки, невідоме = `null`. «Чого бракує» і правила полів (дата не пізніша за сьогодні, вік < 18 → Child, email у
  нижньому регістрі й з «@», лише English / Spanish) рахує код після відповіді моделі, а не промпт.
- Ключ `OPENROUTER_API_KEY` у `src/` читає лише `src/lib/ai/openrouter.ts` з `import "server-only"`; без
  `NEXT_PUBLIC_`; у `.env.local` і Vercel (Production + Preview). Без ключа помічник вимкнений
  (AC-INTAKE-08), форма працює вручну.
- Ланцюжок (лише `:free`): `google/gemma-4-31b-it:free` → `google/gemma-4-26b-a4b-it:free` →
  `nvidia/nemotron-3.5-super-vl:free`; `maxRetries: 0`, таймаут 25 с; будь-який збій → AC-INTAKE-08.
- Людина в контурі: дія чернетки перевіряє `getClaims()` і роль до виклику моделі й нічого не пише; запис —
  `createClientCard` з повторною валідацією й RLS. Окремої `confirmDraft` з набору не додаємо.
- Перевірка якості: 10 golden cases PM — офлайн-реплей записаних відповідей (`MockLanguageModelV4`) у `npm test`
  (CI); живий прогін `npm run eval` вручну зі звітом у `evals/reports/`.

## Розглянуті варіанти

- Claude Agent SDK у функції Vercel — ні: підпроцес Claude Code (~320–342 МБ) не влазить у пакет функції (250 МБ),
  а тут потрібен один виклик моделі, не агентний цикл.
- Пакет `openai` з `baseURL` OpenRouter або `@openrouter/sdk` — ні: немає валідації схемою з типізованими помилками
  й тестових моделей в одному API.
- `openrouter/free` (випадкова безкоштовна модель) — ні: golden cases не відтворюються.
- Правила полів лише в промпті — ні: модель може їх порушити, а рубрика вимагає перевірки кодом там, де це можливо.
- Платний ключ — ні: курс використовує безкоштовні моделі; перехід — заміна фабрики в `src/lib/ai/models.ts`.

## Наслідки

- Простіше: провайдера й модель міняємо в одному файлі; CI не залежить від мережі та ліміту; ворота якості — zod і
  правила коду.
- Складніше: модель може зникнути або впертися в денний ліміт — людина бачить AC-INTAKE-08 і заповнює форму вручну;
  ланцюжок перевіряємо `npm run ai:models`. Записи `tests/fixtures/golden/recorded.json` оновлюємо
  (`RECORD=1 npm run eval`) після кожної зміни промпту (`DRAFT_PROMPT_VERSION`) чи схеми.
- `npm audit` після встановлення показує ті самі знахідки, що й до нього (транзитивні залежності `shadcn`); нові
  пакети їх не додають.
